Système de Permissions Mistral Vibe

Un système de sécurité qui protège vos actions en demandant confirmation avant toute opération à risque.

Comme un vigile numérique qui vérifie chaque accès.

Votre vigile numérique

Demande confirmation avant toute action à risque, protégeant ainsi votre environnement.

Partie 1

Niveaux de Permission

Les fondations du système de sécurité

✅ ALWAYS

Explication : L'outil s'exécute automatiquement.

Exemple : Lecture de fichiers dans le workspace.

❌ NEVER

Explication : L'outil est toujours bloqué.

Exemple : Commandes dangereuses comme rm -rf.

⚠️ ASK

Explication : Demande confirmation à l'utilisateur.

Exemple : Écriture de fichiers, commandes bash.

📋 Allowlist

Explication : Liste des actions toujours autorisées.

Exemple : git status, ls.

🚫 Denylist

Explication : Liste des actions toujours interdites.

Exemple : sudo, rm -rf /.

🔐 Fichiers sensibles

Explication : Fichiers avec des secrets.

Exemple : .env, .ssh/.

Ordre de Priorité

1. NEVER → Bloque systématiquement

2. ALWAYS → Autorise (sauf exceptions)

3. ASK → Demande confirmation

Scénarios Pratiques

1

Lecture dans le workspace

Autorisé sans demander (ALWAYS implicite)

2

Écriture dans le workspace

Demande confirmation (ASK)

3

Accès hors workspace

Demande confirmation même avec ALWAYS

4

Fichier .env

Demande confirmation même avec ALWAYS

5

Commande allowlistée

Autorisé sans demander (ex: git status)

6

Commande denylistée

Bloqué ou demande confirmation (ex: sudo)

En cas de refus ?

L'agent reçoit : Message d'erreur avec decision=SKIP

L'agent continue : ✅ Oui, passe à l'étape suivante

Journalisé : ✅ Oui, dans les logs
